AI-IM 工具系统详细设计文档
版本：v1.0
日期：2025-05-30
技术栈：Java + LangChain4j + MySQL + Redis
关联系统：AI-IM 多 Agent 聊天平台

1. 概述
   1.1 背景
   为了让 AI Agent 能够执行各种任务，需要构建一套灵活、安全、可管理的工具（Tools）系统。工具分为本地工具（如文件读写）和外部工具（如 MCP 服务），需要统一注册、路由、权限控制和审计。

1.2 设计目标
工具路由：透明调用本地或远程工具，业务层无感知。

工具可管理：工具元数据持久化，支持查询、绑定 Agent、启用/禁用。

热插拔与自动注册：新增工具无需重启，支持 Agent 自我进化。

权限分级：危险工具需人工确认。

工具发现：提供 search_tools 元工具，按需加载。

参数动态补全：自动注入会话上下文（用户、Agent 等）。

调用追踪与审计：全链路记录，危险操作留痕。

4.3 ToolInvocationInterceptor（调用拦截器）
在 LangChain4j 的 ToolProvider 基础上封装一层，拦截所有工具调用：

java
public class ToolInvocationInterceptor implements ToolProvider {
private final ToolRegistry registry;
private final ToolAuditLogger auditLogger;
private final ToolConfirmationManager confirmationManager;

    @Override
    public ToolExecutionResult execute(ToolCall call, ToolContext context) {
        // 1. 检查权限，若需确认则挂起
        ToolMetadata meta = registry.getMetadata(call.name());
        if (meta.getRiskLevel() == DANGEROUS || meta.getRiskLevel() == ADMIN) {
            if (!context.isConfirmed()) {
                String requestId = confirmationManager.requestConfirmation(call, meta);
                return ToolExecutionResult.pending(requestId);
            }
        }

        // 2. 动态补全参数
        enrichParameters(call, context);

        // 3. 路由并执行
        ToolExecutor executor = registry.getExecutor(call.name());
        String result = executor.execute(call, context);

        // 4. 审计日志
        auditLogger.log(call, meta, context, result);

        return ToolExecutionResult.success(result);
    }
}
5. 工具动态管理与热插拔
   5.1 自动注册
   本地工具：Spring 启动时扫描所有 @Tool 注解的方法，若 t_tool 中不存在则自动插入，否则更新描述/参数。

MCP 工具：通过管理 API 注册，或由 MCP Gateway 自动发现。

脚本工具：通过上传脚本生成一条 SCRIPT 类型的工具记录。

5.2 热插拔实现
新增/修改工具记录（操作 DB）。

调用 ToolRegistry.reload() 刷新内存。

若为本地工具且对应类未加载，可利用 GroovyShell 或动态类加载器加载新 class；脚本工具动态编译执行。

提供管理接口：POST /admin/tools/reload。

5.3 Agent 与工具的绑定
在 Agent 配置（t_agent 或新表）中存储 tools 字段（JSON 数组），上下文组装时只加载该 Agent 绑定的工具列表。公共工具默认对所有 Agent 可见。

6. 权限分级与确认机制
   6.1 风险等级
   NORMAL：直接执行。

DANGEROUS：需要用户在前端确认。

ADMIN：需要管理员额外审批（可选）。

6.2 确认流程(可以暂时不用实现，遇到危险命令打印一条warn日志)
LLM 调用 DANGEROUS 工具，拦截器生成 requestId 并存入 Redis（TTL 5 分钟）。

返回给前端 ToolConfirmationRequired 事件，包含工具名、参数、风险说明。

用户点击“确认”，前端调用 /confirm-tool 接口（携带 requestId）。

后端从 Redis 取出 ToolCall 上下文，标记 confirmed=true，重新进入执行流程。

执行结果继续回填给 LLM，生成最终回复。

6.3 交互设计要点
对话需支持“挂起”状态，用 WebSocket 或异步轮询告知前端等待。

确认接口需做身份校验，防止越权操作。

7. 工具查询工具（search_tools）
   7.1 元工具定义
   系统预置一个 search_tools 工具，参数：keyword（关键词）、limit（返回数量）。
   实现：

java
@Tool("搜索可用工具，输入关键词返回匹配的工具列表")
public String searchTools(String keyword, int limit) {
List<ToolMetadata> results = registry.searchTools(keyword);
return results.stream()
.limit(limit)
.map(t -> String.format("- %s: %s", t.getName(), t.getDescription()))
.collect(Collectors.joining("\n"));
}
7.2 按需加载策略
上下文组装时，只发送常用工具（如最近使用、高频）加上 search_tools，总数 ≤ 10。

LLM 需要更多工具时先调 search_tools，后续交互再动态加载完整 spec。

9. 调用链路追踪与审计
   9.1 审计日志表 t_tool_audit_log
   ```sql
   CREATE TABLE IF NOT EXISTS `t_tool_audit_log` (
   `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
   `code` VARCHAR(100) NOT NULL DEFAULT '',
   `tool_code` VARCHAR(100) NOT NULL DEFAULT '' COMMENT '工具编码',
   `tool_name` VARCHAR(100) NOT NULL DEFAULT '',
   `agent_code` VARCHAR(60) NOT NULL DEFAULT '',
   `user_code` VARCHAR(60) NOT NULL DEFAULT '',
   `conversation_code` VARCHAR(100) NOT NULL DEFAULT '',
   `request_params` JSON COMMENT '调用参数（脱敏后）',
   `response_summary` VARCHAR(500) DEFAULT '' COMMENT '结果摘要',
   `status` VARCHAR(20) NOT NULL DEFAULT 'SUCCESS' COMMENT 'SUCCESS, FAIL, PENDING, CANCELLED',
   `risk_level` VARCHAR(20) NOT NULL DEFAULT 'NORMAL',
   `execution_time_ms` INT DEFAULT 0,
   `error_message` TEXT,
   `trace_id` VARCHAR(100) NOT NULL DEFAULT '',
   `create_time` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
   INDEX `idx_audit_tool` (`tool_code`, `create_time` DESC),
   INDEX `idx_audit_agent` (`agent_code`, `create_time` DESC),
   INDEX `idx_audit_user` (`user_code`, `create_time` DESC),
   UNIQUE INDEX `udx_audit_code` (`code`)
   ) COMMENT '工具调用审计日志表';
   
   ```
   9.2 日志记录要点
   参数脱敏：标记敏感字段（如密码）不记录原值，替换为 ***。

执行耗时：System.currentTimeMillis() 差值。

TraceId：贯穿单次对话调用链，便于排查。

异步写入，不阻塞主流程。

10. 扩展点（第一期可不做，但要预留）
    工具结果缓存：读类型工具基于参数 hash 缓存结果，Redis 实现，t_tool.cacheable 控制。

工具超时与熔断：基于 timeout_ms 限流，使用 Resilience4j 或线程池 Future.get(timeout)。

工具组合编排（Skill）：内置多个工具的顺序调用能力。

参数级权限：危险工具内部校验，如邮件只能发给白名单域名。

工具版本兼容：parameters_schema 带 version，旧参数自动转换。
