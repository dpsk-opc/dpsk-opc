# OPC-CAT 设计原则

**版本**: v1.0.0  
**日期**: 2026-04-20  
**状态**: 初始版本

---

## 1. 核心理念

### 1.1 设计哲学

**「极简外壳 + 渐进内核」**

> 应用像一个精心设计的瑞士军刀：日常使用时只需一把小刀，需要时才发现它有开瓶器、剪刀、螺丝刀...但小刀从未消失。

### 1.2 核心原则

| 原则 | 说明 | 违反后果 |
|------|------|----------|
| **零干扰** | 核心功能不因扩展而增加认知负担 | 用户流失、功能闲置 |
| **一触即达** | 任何功能 ≤ 3 步可达 | 功能变成摆设 |
| **视觉统一** | 所有层级使用相同设计语言 | 体验割裂、学习成本增加 |
| **可逆优先** | 所有危险操作可撤销 | 用户不敢使用、功能受限 |

## 2. 分层架构

### 2.1 四层模型

```
┌─────────────────────────────────────────────────────────────────┐
│  L0: 核心层 (Core)                                              │
│  ─────────────────────────────────────────────────────────────  │
│  定义：应用的主功能，用户第一眼看到的全部                          │
│  原则：永不改变，不管添加多少功能                                  │
│  示例：聊天输入框、日历视图、文档编辑区                            │
├─────────────────────────────────────────────────────────────────┤
│  L1: 触达层 (Access)                                            │
│  ─────────────────────────────────────────────────────────────  │
│  定义：进入其他功能的入口，低存在感                                │
│  原则：hover 显示，平时隐藏                                       │
│  示例：汉堡菜单 (☰)、头像下拉、浮窗按钮                           │
├─────────────────────────────────────────────────────────────────┤
│  L2: 功能层 (Feature)                                           │
│  ─────────────────────────────────────────────────────────────  │
│  定义：某一功能域的所有操作集合                                    │
│  原则：独占式面板，不影响 L0                                      │
│  示例：侧边栏抽屉、设置面板、文件浏览器                           │
├─────────────────────────────────────────────────────────────────┤
│  L3: 详情层 (Detail)                                            │
│  ─────────────────────────────────────────────────────────────  │
│  定义：复杂表单、列表、编辑器等                                   │
│  原则：按需加载，仅在明确需要时出现                                │
│  示例：Agent 编辑器、订单详情、报表查看                           │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 层级关系图

```
                    用户视角
                    
        ┌─────────────────────────┐
        │                         │
        │     L0 核心层（始终可见） │
        │     ████████████████    │
        │                         │
        │  ┌─────────────────┐    │
        │  │ L1 入口点        │────┼── hover / 点击
        │  └─────────────────┘    │
        │         │               │
        │         ▼               │
        │  ┌─────────────────┐    │
        │  │ L2 功能面板      │    │
        │  │ ████████████████│────┼── 侧滑 / 展开
        │  │ │ L3 详情      │ │    │
        │  │ └──────────────┘ │    │
        │  └─────────────────┘    │
        │                         │
        └─────────────────────────┘
```

### 2.3 层级选择指南

| 场景 | 推荐层级 | 说明 |
|------|----------|------|
| 主功能入口 | L0 | 始终可见的核心功能 |
| 导航切换 | L1 → L2 | 汉堡菜单或标签栏 |
| 列表操作 | L2 | 列表 + 展开详情 |
| 表单填写 | L3 | 模态框或全屏表单 |
| 预览/确认 | L3 | 模态框叠加在 L2 上 |

## 3. 交互模式库

### 3.1 侧边栏模式（推荐用于 Agent 管理）

```
初始状态：
┌────┐
│ ☰  │  ← L1 悬浮入口（固定左侧边缘）
└────┘

         [L0 核心区域保持不变]

展开状态：
┌────────────┬───────────────────────────────┐
│ ← 返回     │                               │
│────────────│                               │
│ 🤖 Agent   │                               │
│ 📜 会话    │         L0 核心区域            │
│ ⚙️ 设置    │         （半透明遮罩）         │
│            │                               │
│────────────│                               │
│ v1.0.0     │                               │
└────────────┴───────────────────────────────┘
  ↑
  L2 侧边栏（从左滑入，宽度 240-280px）
```

**实现要点：**
- 遮罩层使用 `rgba(0,0,0,0.45)` 半透明黑色
- 侧边栏动画：`transform: translateX(-100%)` → `translateX(0)`
- 提供「返回」或「关闭」按钮

### 3.2 快捷操作收拢模式

适用于：用户头像、文件右键菜单

```
┌─────────────────────────────────────┐
│  头像 ▼ │                         │
└─────────┴─────────────────────────┘
           │
           ▼ 点击展开
┌─────────────────────────────────────┐
│  👤 张三                        │
│──────────────────────────│
│  🔄 切换 Agent          │  ← L3 菜单项
│  ⚙️ 设置               │
│──────────────────────────│
│  🚪 退出登录             │
└─────────────────────────────────────┘
```

### 3.3 列表 + 展开模式

适用于：Agent 列表、订单列表、消息列表

```
┌─────────────────────────────────────┐
│  Agent 管理              [+ 新建]  │
├─────────────────────────────────────┤
│  🤖 秘书                    →      │
│  👥 engineering                       │
│     🤖 前端工程师           →      │
│     🤖 后端工程师           →      │
│  👥 design                           │
│     🤖 UI 设计师             →      │
└─────────────────────────────────────┘
       │
       ▼ 点击「前端工程师」
       
┌─────────────────────────────────────┐
│  ← 返回    前端工程师       [编辑]  │
├─────────────────────────────────────┤
│                                     │
│  描述：专业前端开发工程师           │
│                                     │
│  技能：                              │
│  • React                            │
│  • TypeScript                       │
│  • CSS/Sass                        │
│                                     │
│  ─────────────────────────────     │
│  [删除]              [开始对话]     │
└─────────────────────────────────────┘
```

### 3.4 空状态引导模式

适用于：首次使用、功能无数据时

```
┌─────────────────────────────────────┐
│                                     │
│           🤖                        │
│                                     │
│     还没有配置 Agent                 │
│     点击「新建」开始使用             │
│                                     │
│     [+ 新建 Agent]                  │
│                                     │
└─────────────────────────────────────┘
```

### 3.5 确认操作模式

适用于：删除、批量操作、危险操作

```
┌─────────────────────────────────────┐
│                                     │
│    ⚠️ 确认删除                       │
│                                     │
│    确定要删除「前端工程师」吗？       │
│    此操作无法撤销。                  │
│                                     │
│    ─────────────────────────────    │
│                                     │
│    [取消]           [确认删除]       │
│    (次要样式)        (危险样式/红色) │
│                                     │
└─────────────────────────────────────┘
```

## 4. 组件规范

### 4.1 配色系统

| 用途 | 颜色 | 说明 |
|------|------|------|
| 主色 | `#1890ff` | 品牌色、主要按钮、链接 |
| 成功 | `#52c41a` | 成功状态、确认操作 |
| 警告 | `#faad14` | 警告状态、待处理 |
| 危险 | `#ff4d4f` | 删除、错误、危险操作 |
| 背景 | `#ffffff` | 主背景 |
| 文字 | `#262626` | 主文字 |
| 次要文字 | `#8c8c8c` | 辅助说明 |
| 边框 | `#d9d9d9` | 分隔线、边框 |
| 遮罩 | `rgba(0,0,0,0.45)` | 侧边栏遮罩 |

### 4.2 间距系统

基于 8px 网格：

| 名称 | 值 | 用途 |
|------|-----|------|
| xs | 4px | 紧凑元素内部 |
| sm | 8px | 元素间距 |
| md | 16px | 区块内间距 |
| lg | 24px | 区块间间距 |
| xl | 32px | 大区块间距 |
| xxl | 48px | 页面边距 |

### 4.3 圆角规范

| 元素 | 圆角值 |
|------|--------|
| 按钮 | 6px |
| 卡片 | 12px |
| 输入框 | 6px |
| 模态框 | 12px |
| 头像 | 50% (圆形) |

### 4.4 图标规范

- **来源**：Ant Design Icons (@ant-design/icons)
- **大小**：16px (小) / 20px (中) / 24px (大)
- **颜色**：跟随文字颜色

### 4.5 字体规范

| 用途 | 大小 | 字重 | 行高 |
|------|------|------|------|
| 页面标题 | 20px | 600 | 1.4 |
| 卡片标题 | 16px | 600 | 1.5 |
| 正文 | 14px | 400 | 1.6 |
| 辅助文字 | 12px | 400 | 1.5 |

## 5. 功能设计检查清单

每次新增功能时，必须逐项确认：

### 5.1 层级判断

```
□ 这个功能属于哪个层级？
□ 能否复用现有层级，而非创建新层级？
□ 新层级是否破坏了原有的功能层级？
```

### 5.2 极简检查

```
□ 核心用户（不探索功能的用户）能否正常工作？
□ 新增入口是否隐藏在现有交互中？
□ 页面首次加载时是否只显示必要元素？
□ 进阶功能是否有合理的渐进披露？
```

### 5.3 可用性检查

```
□ 操作路径是否 ≤ 3 步？
□ 是否有合理的默认值？
□ 是否有空状态引导？
□ 是否有操作成功/失败的反馈？
□ 危险操作是否有二次确认？
```

### 5.4 一致性检查

```
□ 是否使用了项目统一的配色？
□ 是否使用了间距系统的标准值？
□ 是否使用了现有的组件模式？
□ 交互行为是否与其他页面一致？
```

## 6. 扩展性指南

### 6.1 未来功能预估

基于项目路线图，可能增加的功能：

| 功能 | 建议层级 | 说明 |
|------|----------|------|
| 工作流编排 | L2 → L3 | 侧边栏 + 全屏编辑器 |
| 插件市场 | L2 → L3 | 侧边栏 + 详情页 |
| 使用统计 | L2 | 侧边栏面板 |
| 多语言 | L2 | 设置子面板 |
| 主题切换 | L3 | 设置子页面 |
| 导出/导入 | L3 | 设置子页面 |

### 6.2 添加新功能的决策流程

```
1. 用户提出需求
       │
       ▼
2. 判断：这是「核心功能」还是「扩展功能」？
       │
       ├─ 核心 → 放在 L0，但考虑是否可以通过 L1 入口控制显示
       │
       └─ 扩展 → 继续判断
                 │
                 ▼
3. 判断：是否可以使用现有层级模式？
       │
       ├─ 是 → 直接实现
       │
       └─ 否 → 继续判断
                 │
                 ▼
4. 判断：是否需要新增层级？
       │
       ├─ 是 → 谨慎评估，可能需要重新设计层级架构
       │
       └─ 否 → 寻找替代方案（合并到现有功能、拆分到子功能）
```
